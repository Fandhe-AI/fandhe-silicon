# 契約の明文（公開）

本リポの公開 API が示す振る舞いの契約を、背後実装（Metal / Vulkan / CUDA / CPU）ごとに
まとめて置くディレクトリ。各記述は公開 API の rustdoc と同じ内容とし、
本リポのコードと公開テストで確かめられる事実だけを書く。
spec との対応は spec の TASK-2・TASK-3・TASK-45 のポインタで参照する。
公開してよい範囲は [spec-confidentiality](../../.claude/rules/spec-confidentiality.md) に従う。

## 置き場と構成

- 契約のまとめは `docs/contract/` に置く
- ファイルは `docs/spec/04-behavior/` の項目ファイル単位で 1 つとし、名前は項目 ID の接頭辞の小文字にする（例: `xxx.md`）
- ファイルは、対応するコードと公開テストを入れる PR で初めて作る。事前に空ファイルや一覧を作らない

## 記述の書式

1 つの操作・型につき、次の要素を書く。

| 要素 | 内容 |
| ---- | ---- |
| 見出し | 公開 API のパス（`crate::型` / `crate::関数`） |
| 項目 ID | 対応する `04-behavior/` の項目 ID（ポインタのみ） |
| 提供の表 | 背後実装（Metal / Vulkan / CUDA / CPU）ごとに「提供」または「非提供」。非提供の場合は能力の問合せが返す値を書く |
| エラーの形 | 共通エラー型のどのバリアントを、どの条件で返すか |
| 確かめるテスト | 振る舞いを確かめる公開テストのパス |

### 書かないもの

- 理由・代替案・優先度・状態・未実装の予定・計測値・経緯・内部判断
- 項目 ID の一覧・件数・集計、複数項目をまたぐ要約・索引
- spec の文・表・節の書き写しや言い換え

## 非公開側との分担

- 決定の記録の本体（操作・型の案、理由、判断）は private spec 側に置く。本リポでは ID・パスのポインタだけで参照する
- 契約の元になる `04-behavior/` の確定は spec 側の手順に従う。手順の詳細は本リポに書かない

## 更新の順

1. spec 側で `04-behavior/` の該当項目を先に更新・確定する（唯一の正）
2. 確定後に、本リポでコードと公開テストを実装する
3. 同じ PR で rustdoc と本ディレクトリの記述を追加・更新する
4. 本ディレクトリを `04-behavior/` より先行させない。テストの無い約束は書かない

# セキュリティ規約

## 秘密情報の混入防止（P0）

- 実トークン・実 API キー・資格情報をコード・テスト・fixture・ドキュメントに書かない（例示はダミー値・パターン表記に限る）
- `.env` 等の資格情報ファイルをコミットしない（雛形は `.env.example` のみ）
- hooks・settings.json・`.mcp.json` にシークレットをハードコードしない（`"${VAR:-}"` の環境変数参照とする）

## private spec の漏えい防止（P0）

- [spec-confidentiality](./spec-confidentiality.md) に従う（本リポは public、`docs/spec` は private）

## メモリ安全性（P0）

- safe API から未定義動作（解放後使用・二重解放・範囲外アクセス・データ競合・未同期のデバイスメモリ読み書き）へ到達できる経路を作らない
- `unsafe` の追加・不変条件の変更は `// SAFETY:` の根拠とともにレビューで必ず確認する（[coding-rust](./coding-rust.md)）
- サイズ・オフセット・要素数の計算は `checked_*` で行い、オーバーフローしたままアロケーションやコピーに使わない

## OWASP Top 10 観点（PR 作成前チェック）

| 観点 | 本リポでの具体例 |
| ---- | ---------------- |
| インジェクション | 実行時に組み立てるシェーダ / カーネルソース・コマンドラインへの未検証入力の連結 |
| 不安全な設計 | FFI 境界の検証省略・fail-open なエラー経路・無制限のデバイスメモリ確保 |
| セキュリティ設定ミス | 診断出力でのホスト情報・メモリ内容の過剰な露出 |
| 脆弱な依存 | 未固定バージョン・メンテ停止クレート（[dependency-policy](./dependency-policy.md)） |
| ソフトウェアとデータの整合性 | CI で導入するツールのバージョン固定・SHA256 検証の省略 |

## 運用

- `git commit --no-verify` を使用しない（pre-commit フックを必ず通す）
- セキュリティ上の疑義を発見した場合は作業を中断してユーザーに警告する
